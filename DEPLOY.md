# Инструкция по деплою и публикации на GitHub Pages

Настоящий документ содержит подробное пошаговое руководство по локальной проверке, загрузке репозитория и автоматической публикации сайта стоматологической клиники на **GitHub Pages**.

---

## 1. Локальная установка и проверка сборки

Перед загрузкой проекта на GitHub убедитесь, что локальная сборка выполняется без ошибок.

```bash
# 1. Установка зависимостей с помощью воспроизводимого lock-файла
npm ci

# 2. Запуск локальной production-сборки
npm run build

# 3. Локальный просмотр собранного статического сайта (dist)
npm run preview
```

Для проверки работы ресурса в подпапке репозитория (например, `/dentalclinic/`) можно запустить превью с параметром `--base`:
```bash
npx vite preview --base=/dentalclinic/
```

---

## 2. Загрузка проекта в GitHub-репозиторий

Если git-репозиторий еще не инициализирован локально, выполните следующие команды в терминале из корневой папки проекта:

```bash
# Инициализация git
git init

# Добавление файлов в индекс (файлы из .gitignore будут пропущены)
git add .

# Создание первого коммита
git commit -m "feat: prepare dental landing page for GitHub Pages deployment"

# Переименование основной ветки в main
git branch -M main

# Связывание с вашим удаленным репозиторием на GitHub
# (замените URL на адрес вашего репозитория)
git remote add origin https://github.com/USERNAME/REPOSITORY.git

# Отправка исходников в ветку main на GitHub
git push -u origin main
```

---

## 3. Настройка GitHub Pages в репозитории

После успешной загрузки кода в GitHub:

1. Перейдите на страницу вашего репозитория на **GitHub.com**.
2. Откройте вкладку **Settings** (Настройки) верхнего меню.
3. В левом боковом меню выберите раздел **Pages**.
4. В секции **Build and deployment** найдите выпадающий список **Source** (Источник).
5. Выберите значение **GitHub Actions** (вместо *Deploy from a branch*).

---

## 4. Запуск и отслеживание публикации

После выбора **GitHub Actions** в качестве источника:

* Сборка и деплой запускаются **автоматически** при каждом push-коммите в ветку `main`.
* Также публикацию можно запустить вручную:
  1. Перейдите во вкладку **Actions**.
  2. В левом списке выберите workflow **Deploy landing page to GitHub Pages**.
  3. Нажмите кнопку **Run workflow** → выберите ветку `main` → подтвердите запуск.
* Во вкладке **Actions** вы сможете наблюдать за статусом выполнения шагов `Build` и `Deploy`.

---

## 5. Где найти адрес опубликованного сайта

После успешного выполнения обоих шагов workflow:
1. Перейдите во вкладку **Settings** → **Pages**.
2. Вверху страницы появится зелёный блок с URL вашего опубликованного сайта:
   `https://USERNAME.github.io/REPOSITORY/`
   *(Если репозиторий назван `USERNAME.github.io`, то адрес будет `https://USERNAME.github.io/`).*
3. Также ссылку на деплой можно найти в боковом блоке **Environments** (`github-pages`) на главной странице репозитория.

---

## 6. Как обновлять сайт

Для внесения последующих изменений:
1. Внесите необходимые правки в код проекта локально.
2. Сделайте коммит и отправьте изменения в ветку `main`:
   ```bash
   git add .
   git commit -m "update: refresh clinic services and hours"
   git push origin main
   ```
3. GitHub Actions автоматически подхватит push, соберет проект и обновит опубликованный сайт.

## 7. Чек-лист реальных данных перед публичным использованием

До начала полноценной эксплуатации замените демонстрационные данные:

* [ ] **Входные данные клиники**: Заполните телефон, адрес, e-mail, часы работы и ссылку на карту в файле `src/config/clinicConfig.ts`.
* [ ] **Медицинская лицензия и реквизиты**: Заполните юридические данные в `src/components/Footer.tsx` и `src/components/PrivacyModal.tsx`.
* [ ] **Интеграция формы записи**:
  * Если используется CRM/API: установите `VITE_IS_DEMO_MODE=false` и укажите URL эндпоинта в `VITE_API_ENDPOINT` (через переменные окружения или в `src/services/bookingApi.ts`).
  * Внимательно проверьте настройки CORS на вашем сервере приема заявок.
* [ ] **Отзывы и фотографии**: Замените демонстрационные карточки отзывов и стоковые изображения на реальные материалы клиники.

## 8. Решение возможных проблем (Troubleshooting)

### 🚨 404 при загрузке стилей, скриптов или картинок
* **Причина**: Неверный базовый путь `base` в Vite.
* **Решение**: Проект настроен так, что `vite.config.ts` автоматически считывает имя репозитория через `process.env.GITHUB_REPOSITORY` и шаг `actions/configure-pages@v5`. Убедитесь, что во вкладке Settings -> Pages источником выбран **GitHub Actions**.

### 🚨 Ошибка выполнения workflow ("Permission denied")
* **Причина**: Недостаточно прав у токена GitHub Actions.
* **Решение**: Файл `.github/workflows/deploy.yml` уже содержит все необходимые разрешения (`contents: read`, `pages: write`, `id-token: write`). Также проверьте в Settings → Actions → General, что в секции *Workflow permissions* включено *Read and write permissions*.

### 🚨 Ошибка сборки на шаге `npm ci`
* **Причина**: Несогласованность файла `package-lock.json` и `package.json`.
* **Решение**: Выполните локально `npm install`, убедитесь, что `package-lock.json` обновлен и закоммичен в git.

### 🚨 Форма пишет «Демонстрационный режим: заявка не отправлена»
* **Причина**: На GitHub Pages нет бэкенда (это статический хостинг).
* **Решение**: Это предусмотренное поведение по умолчанию. Заявки отправятся на внешний сервер только после подключения внешнего API в `src/services/bookingApi.ts` и отключения демо-режима (`VITE_IS_DEMO_MODE=false`).
